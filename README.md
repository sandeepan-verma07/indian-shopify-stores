## 1. Definitions & assumptions

The brief leaves a few things open. These are the choices I made:

- **"Shopify store"** = a live storefront where at least 2 of 4 independent Shopify signals agree (DNS, `/meta.json`, HTML, HTTP headers). For the final list I require **all 4**. Password-protected ("opening soon"), empty (0 products) and unreachable stores are excluded.
- **"Indian"** = the business itself is registered in India, read from the store's own Shopify settings (`/meta.json`): **country = IN, currency = INR, and an Indian state/UT**. All three must hold. Then I additionally require **proof on the website itself**: a valid +91 phone number, a GSTIN, or an Indian PIN code. "Ships to India" is *not* enough (e.g. Kylie Cosmetics ships to India but is American).
- **Edge cases (brief asks about these):**
  - *Indian brand on a `.com` domain* → included. Two thirds (67%) of the final list is on `.com` / `.co` / `.shop` etc. That is why I used Chrome UX Report India as a source, not just `.in` domains.
  - *`.in` domain that isn't Indian* → the domain name is never used as proof, only as a weak hint.
  - *Globally-hosted / foreign-registered brand selling in INR* (e.g. registered in Canada, Australia, Sri Lanka, but prices in ₹) and *Indian-registered brand selling only in USD* (exporters) → **not** in the main list. They are listed separately with the reason in [`data/edge_cases.csv`](data/edge_cases.csv) (9 stores), because I couldn't be certain either way. With the brief's "quality over count" rule, excluding doubtful stores is the safer call.
- **Primary domain** = the domain the store itself reports in `/meta.json` (custom domain). Duplicates (one store reachable on several domains, e.g. `.in` and `.com`) are merged by Shopify's internal `myshopify_domain`, which is unique per store.
- **Every field is copied from the store's own website** — nothing is invented. If a field can't be found it stays empty (and the store doesn't make the final list, see §4).
- **Category** = one label from a fixed list of 20 categories (+ an audience label for apparel, e.g. "Apparel & Fashion (Women)"), decided from the store's own product list.
- **Tagline** = the store's own text, verbatim: its meta description → About page → homepage title (in that order), trimmed to whole sentences (≤ 300 characters). Offer banners ("Use code FESTIVE10…") are not accepted as a tagline.
- **Logo** = the URL of the brand logo image (never the favicon). Not downloaded; every URL was checked to load.
- **"Twitter" column** holds Twitter **or** X links (`twitter.com/…` and `x.com/…`).
- **Final size**: 1,614 stores passed everything; I deliver the **top 1,000** by a transparent quality score (§4.3). The other 614 are in `data/all_stores.csv` (`passes_all_checks = True`).

## 2. Approach, step by step

```
Step 1  sourcing/tranco.py, crux.py, merge.py   candidate domains                      718,855
Step 2  sourcing/dns_check.py                   DNS points to Shopify (top 50,000)       4,160
Step 3  utils/fetcher.py                        polite, cached fetcher (used by all steps below)
Step 4  verify/shopify_check.py                 2+ of 4 Shopify signals, live           3,966
Step 5  verify/india_score.py                   IN + INR + Indian state, deduplicated    3,837
Step 6  extract/run_extract.py (+ one file per field)   extract the 7 fields
        extract/refine.py                       clean contacts, GSTIN state check, taglines from About pages
        extract/ai_category.py                  second opinion on category (embedding model)
        verify/live_checks.py                   logo loads? email domain receives mail?
Step 7  build_final.py                          12 checks → rank → best 1,000 + reports/funnel.md
Step 8  verify/audit.py                         re-check every delivered field on the live site
```

A small **golden set** ([`data/golden_set.csv`](data/golden_set.csv)) was built by hand before writing any code: 10 Indian Shopify stores, 5 foreign Shopify stores (Gymshark, Allbirds, ColourPop, Kylie Cosmetics, Fashion Nova) and 5 Indian non-Shopify sites (Flipkart, Myntra, Nykaa, Ajio, Tata CLiQ). Every step was tested on it first (all steps 20/20 or 10/10 correct).

### Step 1 — Candidate domains (free, public lists)

- **Tranco top-1M** (list `L5PZ4`) → only the `.in` family (`.in`, `.co.in`, …; government/education suffixes removed) → 9,254 domains.
- **Chrome UX Report (CrUX), India** — Google's public dataset of the origins Indian Chrome users actually visit, queried for free on BigQuery (August 2026 data, 1,000,000 origins, each with a popularity rank):
  ```sql
  SELECT DISTINCT origin, experimental.popularity.rank AS source_rank
  FROM `chrome-ux-report.experimental.country`
  WHERE yyyymm = 202608 AND country_code = 'in'
  ```
  Exported to `data/raw/crux_in.csv` → normalised to registered domains with `tldextract` → 716,973 domains.
- **Merged** → **718,855 unique candidates**; all 20 golden-set domains are present.

Why these two: Tranco alone is global and mostly big non-store sites; CrUX India is the key source because it contains Indian brands on `.com`, which a TLD filter misses. Both are free and reproducible.

### Step 2 — DNS pre-filter (cheap, no website is touched)

Every Shopify storefront on a custom domain points its DNS at Shopify: an A record in `23.227.38.0/24` or a CNAME to `shops.myshopify.com`. `dnspython` (async, 30 lookups at a time on 1.1.1.1 / 8.8.8.8) checks `domain` and `www.domain`.

Candidates were checked **most promising first**: domains in both lists → CrUX by popularity → Tranco-only (which gave 0 Shopify hits). I stopped after the **top 50,000** (~12 min): **4,160 Shopify domains** — already 4× the target. Resumable; timeouts are retried.

### Step 3 — A polite, cached fetcher (`utils/fetcher.py`)

Used by every step that touches a website:
- checks **robots.txt** before every request (401/403 on robots.txt = disallow all);
- **one request at a time per site**, ≥ 1 s apart;
- a **global limit of 4 requests/second across all sites** — all stores sit on Shopify's shared servers, which rate-limit per visitor, not per store (lesson learned, see §5);
- on **HTTP 429 everyone pauses** (Retry-After, else 10 / 30 / 60 s backoff);
- every answer is **cached on disk** (`data/cache/`), so re-runs don't hit the sites again; temporary failures (429/5xx) are never cached;
- identifies itself honestly: `RivyouStoreResearchBot/1.0 (student assignment; polite, cached crawler)`.

### Step 4 — Is it really Shopify? (`verify/shopify_check.py`)

Four independent signals per domain:

| Signal | How |
|---|---|
| DNS | Step 2 |
| `/meta.json` | Shopify's public store endpoint; must be real JSON with a `myshopify_domain` (Tata CLiQ returns HTML with status 200 — rejected) |
| HTML | `cdn.shopify.com`, `window.Shopify`, `Shopify.theme`, `.myshopify.com` in the homepage |
| Headers | `powered-by: Shopify` or `x-shopid` |

≥ 2 signals → Shopify (**4,050**). **False positives removed: 110 domains** whose DNS pointed at Shopify but nothing else agreed (dead/unconfigured stores). Fashion Nova (Shopify, but blocks `/meta.json`) is correctly recognised from HTML + headers. Store state is recorded: **3,966 live**; password-protected, empty and unreachable stores are dropped.

### Step 5 — Is it really Indian? (`verify/india_score.py`)

From `/meta.json` (the owner's own Shopify settings): country, currency, province (state). Old state names are normalised (Orissa → Odisha, Daman and Diu → Dadra and Nagar Haveli and Daman and Diu, …).

- **High confidence** = country IN **and** currency INR **and** an Indian state → **3,837 stores**.
- Doubtful ones (registered abroad but sells in INR, registered in India but sells in USD, no state) → [`data/edge_cases.csv`](data/edge_cases.csv) with the reason.
- **Deduplication** by `myshopify_domain`, keeping the store's own primary domain (e.g. `snitch.co.in` → `snitch.com`).
- Of the 3,966 live Shopify stores, 118 were not registered in India (US 55, GB 13, HK 10, …) — these are the non-Indian false positives the funnel removes.

### Step 6 — Extracting the 7 fields (`extract/`)

For each store, up to 6 pages (all via the polite fetcher): homepage, `/pages/contact`, `/policies/contact-information`, `/policies/privacy-policy`, `/products.json?limit=30`, and the About page (found by following the store's own menu link).

| Field | Method |
|---|---|
| Domain URL | primary domain from Step 5 |
| Emails | `mailto:` links + visible text (not scripts); junk filtered (image names, `@shopify.com`, theme placeholders like `info@yourstore.com`); malformed links cleaned (`mailto:`, `%20`, `email:` prefixes, two addresses in one link) |
| Phones | Google's `phonenumbers` library: only **valid Indian numbers**, normalised to `+91…` |
| Socials | `<a href>` links matched per platform; share buttons, posts and Shopify's own pages ignored; a link containing the brand name is preferred |
| Category | keyword rules over the store's own `products.json` (product types count 3×, titles, tags) across 20 categories + audience label for apparel; then confirmed by an AI model (below) |
| Tagline | meta.json description → `<meta name=description>` → `og:description` → About page (meta / first real paragraph) → homepage `<title>` minus the brand. Offer/banner text rejected |
| Logo | Organization logo in the page's JSON-LD (for Google) → else an `<img>` in the header whose class/alt/src says "logo"; favicons rejected |
| State | meta.json province, **cross-checked with the GSTIN** if the site shows one: a GST number's first 2 digits are the state code |

**Category, second opinion** (`extract/ai_category.py`): keyword rules can't understand product names like "Air Force 1 Low" or "Dolcevita". A small local embedding model (`all-MiniLM-L6-v2`, sentence-transformers, runs on CPU, no API) turns each product title into a vector and votes for the closest category description. **A store keeps its category only if the keywords and the model agree** (67% did). On a hand-checked sample, every agreeing store was correct; disagreements were mostly messy stores or keyword mistakes (e.g. a bed shop labelled Beauty because of the colour "cream"). The model alone is weaker than the keywords — it's used only as a filter.

**Contact clean-up** (`extract/refine.py`): 43 placeholder emails removed from 28 stores (theme defaults such as `contact@company.com`); contacts appearing on 4+ different stores are flagged as not the store's own (e.g. one phone number on 14 "deals" stores, a dummy toll-free number on 7).

**State cross-check**: GSTIN confirmed the meta.json state for 500 stores; 2 were corrected (meta.json showed Shopify's default first dropdown option, "Andaman and Nicobar Islands"); 21 contradictions (mostly Delhi / Haryana / UP — NCR) were excluded.

**Live checks** (`verify/live_checks.py`): every candidate's logo URL must return an image (59 didn't — mostly deleted files) and every email domain must have mail servers (MX) — 25 didn't, e.g. an email at a domain that no longer exists.

### Step 7 — Selection (`build_final.py`)

A store is considered only if it passes **all 12 checks**:

1. all 4 Shopify signals · 2. category agreed by keywords + model · 3. own email (not placeholder / shared) · 4. own valid +91 phone · 5. at least one social profile · 6. logo found · 7. tagline in the store's own words · 8. state consistent with GSTIN · 9. India proof on the site itself (+91 / GSTIN / PIN) · 10. logo loads · 11. email domain has MX · 12. every field confirmed live (final audit)

**1,614 stores pass.** They are ranked by a transparent score (max 13) that rewards extra certainty and richer data: GSTIN on site +3 · email on the store's own domain +2 · +1 per social profile · model vote share ≥ 60% +1 · 20+ products +1 · About page +1. Ties → more popular first (CrUX rank). The **top 1,000** are delivered.

**Manual corrections** are never made by editing the output: they live in [`data/manual_overrides.csv`](data/manual_overrides.csv) and are applied by the script, so they survive every rebuild and are listed in the report. There is one: `linkcart.in` (Link Locks Pvt. Ltd.) — both methods said "Bags & Luggage", it sells locks.

`build_final.py` also writes [`data/all_stores.csv`](data/all_stores.csv): all 3,837 stores, every field, one pass/fail column per check and a readable `excluded_reason` (e.g. *"state conflict: meta.json says Delhi, GSTIN says Haryana"*).

### Step 8 — Final audit on the live sites (`verify/audit.py`)

The extraction worked from pages saved days earlier. The audit downloads each delivered store's pages **again, fresh**, and checks every field against today's site: `meta.json` still Shopify / IN / INR / same state; **every** listed email and phone still on the site; the Instagram link still on the site; the tagline still where we say it came from. The full per-store log with evidence is [`data/audit_log.csv`](data/audit_log.csv).

- First pass: 946 / 1,000 fully confirmed. Most of the rest were Shopify rate-limiting the audit itself (HTTP 429) → re-checked at 2 requests/second.
- Real findings: **happilo.com** no longer appears to be on Shopify (no `myshopify_domain`, none of its contacts found), **truebrowns.com**'s `meta.json` now returns 404, 4 stores changed their tagline, 9 stores removed one of their phone numbers, and 14 emails were malformed mailto links. The 6 stale stores were replaced by the next-best stores (also audited), outdated phone numbers were dropped, emails were cleaned.
- **Final: 1,000 / 1,000 stores confirmed on the live site, every field** ([`reports/audit.md`](reports/audit.md)). Logos were checked live in the previous step.

## 5. Known limitations & what I'd do at 10× / 100× scale

**Coverage limits of this run**
- Only the **top 50,000 of 718,855 candidates** were DNS-checked (enough for 4× the target). Smaller stores that Indian Chrome users rarely visit aren't in CrUX at all.
- **Only custom-domain stores** are found this way; stores living only on `*.myshopify.com` are mostly invisible to both lists.
- Category is 1 label from 20; multi-category marketplaces get their dominant category.
- "State" is the business address the owner entered in Shopify (confirmed by GSTIN for 23.5% of the final list) — for a few brands this may be the registered office rather than the warehouse.
- WHOIS was not used: `.in` WHOIS is mostly privacy-redacted, and `meta.json` + GSTIN are more reliable.
- Websites change: the audit found ~1–2% of stores had changed something (platform, tagline, a phone number) within 1–3 days of the crawl — the data is a snapshot.

**What breaks at 10× / 100×**
- **Rate limits.** Shopify limits per visitor IP across all its stores. At 4 req/s, 1,000 stores × 6 pages takes ~30 min; 100,000 stores would take ~2 days from one IP. I'd spread work over time, keep the cache, fetch only the pages each field needs, and use `If-Modified-Since` for re-checks.
- **Storage.** One JSON file per cached page (~10 GB here). On Windows the antivirus scanning each file made reading the cache slower than downloading (15 min to parse). At scale: WARC files or SQLite / object storage.
- **DNS.** Public resolvers throttle above ~30 queries/s; 700k domains ≈ 7 h. A local caching resolver (unbound) or zone-file data would be needed.
- **Candidate discovery.** At 100× I'd add sources that list Shopify stores directly: Common Crawl's URL index (pages that load `cdn.shopify.com`), certificate transparency logs (`*.myshopify.com`), and reverse-IP data for `23.227.38.0/24`.

**With more time**
- DNS-check all 718k candidates and add Common Crawl.
- A better category model (a few hundred hand-labelled stores to fine-tune on, or a small LLM with the product list).
- A larger human spot-check for category and "belongs to this store" judgments that a script can't make.
- One `pipeline.py` that runs all steps in order.

**Lessons learned (and fixed)**
- Being polite per site was not enough: ~40 req/s spread over 3,800 stores still triggered Shopify's per-visitor limit → added the global limit and shared pause.
- The fetcher initially cached 429 answers as if they were real pages → temporary failures are now never cached.
- Excel re-saving the CSV damaged Indian characters → output is written as UTF-8 with BOM, and corrections go through `manual_overrides.csv`, never by editing the output.

## 6. How to run

**Requirements:** Python 3.11+, ~15 GB free disk for the page cache, internet. A free Google Cloud account for the one BigQuery query.

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows   (Linux/macOS: source .venv/bin/activate)
pip install -r requirements.txt
```

Always run from the project root:

| # | Command | What it does | Time (my laptop) |
|---|---|---|---|
| 1 | `python -m sourcing.tranco` | Tranco list → `.in` domains | ~1 min |
| 2 | run the SQL in Step 1 on BigQuery, save as `data/raw/crux_in.csv`, then `python -m sourcing.crux` | CrUX India → domains | ~10 min (manual) |
| 3 | `python -m sourcing.merge` | one candidate list | seconds |
| 4 | `python -m sourcing.dns_check --limit 50000` (`--golden` to test) | DNS filter | ~12 min |
| 5 | `python -m verify.shopify_check` (`--golden` to test) | Shopify signals | ~35 min |
| 6 | `python -m verify.india_score` | India filter + dedup | seconds |
| 7 | `python -m extract.run_extract` (`--limit 30` trial, `--skip-fetch` re-parse) | fetch pages + extract fields | ~2.5 h fetch (polite speed) + ~15 min parse |
| 8 | `python -m extract.refine` | contacts, state, taglines | ~5 min |
| 9 | `python -m extract.ai_category` (`--limit 40` trial) | category second opinion (downloads a 90 MB model once) | ~7 min |
| 10 | `python -m verify.live_checks` | logo loads + email MX | ~8 min |
| 11 | `python build_final.py` | checks, ranking, `stores.csv/json`, `reports/funnel.md` | seconds |
| 12 | `python -m verify.audit`, then `python build_final.py` — repeat until it prints "all done" | live re-check of every delivered field; failures are replaced | first run ~2.5 h, re-runs minutes |

A full run from scratch takes roughly **6–7 hours**, almost all of it deliberately slow, polite waiting on websites. Every step caches or resumes, so it can be stopped and restarted.

Not in the repo (large, reproducible from the steps above): the page cache `data/cache/`, `data/raw/`, and the big candidate lists `data/candidates_{tranco,crux,raw}.csv`.
